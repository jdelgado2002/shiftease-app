# ShiftEase Copilot Instructions

## 🚀 Project Setup & Tools

### Package Manager
- This project uses pnpm as the package manager
- Always use pnpm commands instead of npm or yarn
- Example commands:
  ```bash
  pnpm install
  pnpm add <package>
  pnpm remove <package>
  pnpm run <script>
  ```

### Development Environment
- Node.js version: 18+
- Next.js version: 15.2.4
- TypeScript version: 5
- Database: PostgreSQL with Prisma ORM
- Authentication: NextAuth.js
- Testing: Jest + React Testing Library + Playwright

### Project Structure
- `/app` - Next.js app router pages and API routes
- `/components` - Reusable React components
- `/lib` - Utility functions and shared logic
- `/prisma` - Database schema and migrations
- `/types` - TypeScript type definitions
- `/contexts` - React context providers
- `/hooks` - Custom React hooks
- `/styles` - Global styles and Tailwind configuration
- `/public` - Static assets
- `/__tests__` - Test files

### Development Workflow
1. Install dependencies: `pnpm install`
2. Start development server: `pnpm dev`
3. Run tests: `pnpm test`
4. Run E2E tests: `pnpm test:e2e`
5. Generate Prisma client: `pnpm prisma:generate`
6. Run database migrations: `pnpm prisma:migrate`

## 🔒 Security Best Practices

### Authentication & Authorization
- Use proper JWT token handling with HttpOnly cookies
- Implement rate limiting for auth endpoints
- Use bcrypt for password hashing
- Follow the principle of least privilege
- Always verify permissions server-side
- Keep tokens secure using HTTP-only cookies
- Implement proper session management
- Use secure password reset flows

### API Security
- Implement CSRF protection for all mutations
- Use rate limiting for sensitive endpoints
- Validate all input data using Zod schemas
- Sanitize data before storage/display
- Use proper HTTP security headers
- Implement proper error handling without leaking details
- Follow REST best practices
- Use proper HTTP methods and status codes

### Rate Limiting
- Use progressive rate limiting for auth endpoints
- Implement IP-based rate limiting
- Use stricter limits for sensitive operations
- Add proper rate limit headers
- Implement backoff strategies
- Monitor for abuse patterns

### Data Protection
- Use proper input validation
- Implement proper access controls
- Use parameterized queries
- Encrypt sensitive data at rest
- Use secure communication channels
- Implement proper backup strategies
- Follow data retention policies
- Use proper error handling

### Environment & Configuration
- Use proper environment variables
- Never commit sensitive data
- Validate environment variables at startup
- Use proper secrets management
- Implement proper logging
- Use secure defaults
- Follow the principle of defense in depth

## 🛠️ Code Style Guidelines

### TypeScript
```typescript
// Use proper types for security-critical code
interface AuthPayload {
  userId: string;
  organizationId: string;
  role: UserRole;
  permissions: string[];
}

// Use enums for constants
enum UserRole {
  ADMIN = 'admin',
  USER = 'user',
}

// Use proper error handling
try {
  await authenticateUser(credentials);
} catch (error) {
  if (error instanceof AuthError) {
    // Handle specific auth errors
  } else {
    // Handle unknown errors without leaking details
  }
}
```

### API Routes
```typescript
// Use proper validation
const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

// Use proper rate limiting
const rateLimitResult = rateLimit(ip, {
  maxRequests: 5,
  windowMs: 60 * 1000,
  blockDurationMs: 15 * 60 * 1000,
});

// Use proper error responses
if (!rateLimitResult.success) {
  return NextResponse.json(
    { message: "Too many attempts" },
    { status: 429 }
  );
}
```

### Components
```typescript
// Use proper type safety
interface SecureComponentProps {
  data: AuthPayload;
  onAction: (data: SecureData) => Promise<void>;
}

// Use proper error boundaries
export const SecureComponent: FC<SecureComponentProps> = ({
  data,
  onAction,
}) => {
  try {
    // Component logic
  } catch (error) {
    // Handle errors properly
  }
};
```
